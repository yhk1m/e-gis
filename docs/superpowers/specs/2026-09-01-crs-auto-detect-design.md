# 좌표계 자동 감지 · EPSG:3857 변환 설계

작성일: 2026-09-01
상태: 설계 확정

## 무엇을 만드는가

좌표계가 다른 공간데이터를 가져오면 엉뚱한 위치에 그려진다.
가져오는 시점에 원본 좌표계를 알아내 지도 좌표계(EPSG:3857)로 변환한다.
확실하면 조용히, 애매하면 후보를 **지도 위에 미리 보여주고** 고르게 한다.

## 지금 상태

감지 로직이 없는 게 아니라 **로더마다 흩어져 있고 서로 다르다**.

| 로더 | 현재 동작 | 문제 |
|---|---|---|
| GeoJSON | `dataProjection: 'EPSG:4326'` 하드코딩 | 감지 자체가 없다. TM 좌표 자료가 항상 어긋난다 |
| Shapefile | `.prj` 문자열 부분일치 + 좌표 크기 추정 | `EPSG:5185`를 반환하는데 proj4에 정의가 없어 변환이 조용히 깨진다. `proj4.defs`를 `CoordinateSystem`과 중복 등록한다 |
| GeoPackage | `'EPSG:' + srs_id` | 미등록 EPSG면 실패한다 |
| CSV/Excel | `fromLonLat` 고정 | TM 좌표 표는 위경도 범위 검사에 걸려 전 행이 버려진다 |
| DEM | 자체 추론 로직 보유 | 동작은 하지만 규칙이 다른 로더와 다르다 |

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 적용 범위 | 5개 로더 전부를 공통 모듈로 통합 | 형식마다 다른 규칙이 오작동의 뿌리다. 앞으로 어떤 형식이든 같은 근거로 판정된다 |
| 감지 방식 | 좌표 크기 추측 대신 **역방향 검증** | 5186과 5181은 `y_0`만 10만 차이라 크기로는 구분되지 않는다. 되돌려 보면 갈린다 |
| 확신할 때 | 묻지 않고 변환 | 수업 중 클릭이 늘지 않는다 |
| 애매할 때 | 후보를 본 지도에 미리 그려 고르게 한다 | 좌표계 코드를 몰라도 "어디에 찍히는지"로 판단할 수 있다. 교사·학생 모두에게 통한다 |
| 미리보기 구현 | 후보별 미니 지도가 아니라 **본 지도에 임시 레이어** | 미니 지도는 OL 인스턴스를 여러 개 띄워 저사양 기기에서 버벅인다. 본 지도 재사용은 체감이 같으면서 훨씬 가볍다 |
| 좌표계 정의 위치 | `CoordinateSystem` 한 곳 | 지금은 두 곳에 흩어져 정의 누락 버그를 낳았다 |
| 이미 올라간 레이어 재지정 | 이번 범위 밖 | 원본 좌표 보존이 선행돼야 한다. 아래 「범위 밖」 참조 |

## CrsDetector

신규 `src/core/CrsDetector.js`. 지도·DOM에 의존하지 않는 순수 모듈이라 단독으로 테스트된다.

```js
detectCrs({ prj, srsId, geojsonCrs, epsgCode, projParams, sampleCoords })
// →
{
  crs: 'EPSG:5186',
  confidence: 'certain' | 'ambiguous' | 'unknown',
  reason: '.prj의 AUTHORITY 코드',
  candidates: [ { crs, name, reason, center } ]   // center: 변환 결과 중심 [lon, lat]
}
```

입력은 형식마다 **있는 것만** 넘긴다. 없는 키는 그냥 빠진다.

| 로더 | 넘기는 근거 |
|---|---|
| Shapefile | `prj`, `sampleCoords` |
| GeoJSON | `geojsonCrs`(구 규격 `crs` 멤버, 국내 자료에 흔하다), `sampleCoords` |
| GeoPackage | `srsId`, `sampleCoords` |
| CSV/Excel | `sampleCoords` (사용자가 고른 x·y 컬럼의 표본) |
| DEM | `epsgCode`, `projParams`, `sampleCoords`(bbox 모서리) |

### 판정 규칙 (위에서부터, 먼저 걸리는 것이 이긴다)

| 순위 | 근거 | 결과 |
|---|---|---|
| 1 | `.prj`의 `AUTHORITY["EPSG", …]`, GeoPackage `srs_id`, GeoJSON `crs` 이름 | **certain** |
| 2 | `.prj` 투영 파라미터(`lat_0`·`lon_0`·`x_0`·`y_0`·`ellps`)가 알려진 한국 좌표계와 일치 | **certain** |
| 3 | 역방향 검증에서 살아남은 후보가 1개 | **certain** |
| 4 | 역방향 검증에서 살아남은 후보가 2개 이상 | **ambiguous** |
| 5 | 살아남은 후보가 없음 | **unknown** (전체 후보 제시) |

1·2번은 명시적 근거이므로 역방향 검증을 건너뛴다. 다만 결과 좌표가 한국 영역 밖이면
`reason`에 그 사실을 적어 남긴다 — 해외 자료일 수 있으므로 판정을 뒤집지는 않는다.

`certain`이면 조용히 변환한다. `ambiguous`·`unknown`이면 다이얼로그를 띄운다.

### 역방향 검증

이 설계의 핵심이다.

1. 표본 좌표(최대 20개 피처의 첫 좌표)를 뽑는다
2. 후보 좌표계마다 `proj4(후보, 'EPSG:4326', 표본)`으로 되돌린다
3. 결과가 한국 영역(경도 124–132, 위도 33–43) 안에 들어오는 후보만 남긴다
4. 남은 개수로 confidence를 정한다

**단위 온전성 검사를 함께 건다.** 표본이 전부 경위도 범위(|x|≤180, |y|≤90) 안이면
미터 단위 좌표계를 후보에서 빼고, 하나라도 그 범위를 벗어나면 경위도 좌표계를 뺀다.
이게 없으면 파리 좌표 `[2.35, 48.85]`가 3857로도 "세계 안"이라 후보가 둘이 되어
해외 위경도 자료마다 쓸데없이 확인 창이 뜬다.

값의 크기로 짐작하지 않으므로 범위가 겹치는 좌표계도 갈린다.
표본이 한국 밖일 수 있으므로, 후보가 하나도 안 남으면 영역 조건을
전 지구(경도 −180–180, 위도 −85–85)로 완화해 한 번 더 거른다.

## 좌표계 정의 세트

`CoordinateSystem`의 `CRS_DEFINITIONS`를 한국 실무 세트로 보강한다.
ShapefileLoader의 중복 `proj4.defs` 호출은 삭제한다.

| 계열 | 코드 |
|---|---|
| 지리 · 웹 | 4326, 3857 |
| Korea 2000 | 5185(서부), 5186(중부), 5187(동부), 5188(동해), 5181(중부 y_0=500000) |
| Korean 1985 | 5173(서부), 5174(중부), 5176(동부), 5177(동해), 2097(중부 bessel) |
| UTM-K | 5179(GRS80), 5178(bessel) |
| UTM | 32651(51N), 32652(52N) |

`detectProjection`이 반환하던 `EPSG:5185`가 정의에 없던 버그가 여기서 해소된다.

## 로더별 변경

| 로더 | 변경 |
|---|---|
| GeoJSONLoader | 하드코딩된 `dataProjection` 제거, 감지 결과 사용 |
| ShapefileLoader | `detectProjection`·`guessProjectionFromExtent`·중복 `proj4.defs` 삭제 후 위임 (약 90줄 감소) |
| GeoPackageLoader | `srs_id`를 근거로 넘기되, 미등록 EPSG면 역방향 검증으로 대체 |
| TableLoader | `createPointLayer`에 `sourceCrs` 인자 추가. 4326이 아니면 `proj4`로 3857 변환하고, 위경도 범위 검사는 4326일 때만 적용 |
| DEMLoader | 감지만 CrsDetector에 위임. 픽셀 재투영 없이 bbox만 변환하는 현행 동작은 유지한다. `matchKoreanTM`이 중앙경선 125를 5188로 보내던 오류가 함께 해소된다 — 125는 서부원점(5185)이고 5188은 동해원점이다 |
| CoordinateImportPanel | 좌표계 선택 드롭다운 추가. 기본값은 감지 결과 |

다이얼로그가 비동기이므로 `GeoJSONLoader.loadFromString`은 `async`가 된다.
호출자는 `loadFromFile`·`loadFromUrl` 둘뿐이고 이미 비동기라 파급은 없다.
CSV는 다이얼로그 대신 드롭다운을 쓰므로 `createPointLayer`는 동기로 둔다.

## 미리보기 다이얼로그

신규 `src/ui/dialogs/CrsConfirmDialog.js`.

- 후보를 라디오로 나열한다. 각 줄에 코드 · 이름 · 판정 근거 · 변환 결과 위치
- 라디오를 고르면 **본 지도에 임시 레이어로 즉시 그리고 그 범위로 이동**한다
- 임시 레이어는 `mapManager.getMap().addLayer()`로 직접 올린다. LayerManager를 거치지 않으므로 레이어 패널·히스토리·자동저장에 흔적이 남지 않는다
- 미리보기는 표본 500개 피처만 그린다. 대용량에서도 즉시 반응한다
- 후보 목록에 없는 좌표계를 위해 전체 좌표계 드롭다운을 함께 둔다
- 확인 · 취소 · ESC · 오버레이 클릭 **모든 종료 경로가 하나의 `cleanup()`을 거친다**. 임시 레이어가 지도에 남는 것이 이 기능의 유일한 실패 모드이므로 경로를 하나로 모은다
- 아이콘은 선 SVG. 이모지는 쓰지 않는다

반환값은 사용자가 고른 좌표계 또는 `null`(취소). `null`이면 로더는 레이어를 만들지 않는다.

## 테스트 (vitest, 기존 패턴)

- `CrsDetector`: `.prj` WKT 표본별 판정(5179·5186·5174·5181·UTM 52N·WGS84), `srs_id` 경로, GeoJSON `crs` 멤버
- 역방향 검증: 5186 vs 5181이 후보 2개로 갈리는지, 후보 0개일 때 전 지구 완화가 동작하는지
- 각 로더가 감지 결과를 `dataProjection`에 반영하는지
- `CrsConfirmDialog`: 확인·취소·ESC 각 종료 경로에서 임시 레이어가 지도에서 제거되는지

## 범위 밖

**이미 올라간 레이어의 좌표계 재지정.** 피처는 3857로 변환돼 저장되므로,
되돌리려면 레이어에 원본 좌표계를 기록해 두고 3857 → 원본 → 새 좌표계로 두 번
변환해야 한다. 손실은 무시할 수준이지만 레이어 메타·프로젝트 저장 형식이 함께
바뀌므로 별도 작업으로 뺀다. 다만 감지한 원본 좌표계를 `layerManager.addLayer`에 `sourceCrs`로 **기록만** 해 두는 것은
이번 범위에 넣는다. 읽는 곳은 아직 없고, 다음 단계의 발판이 된다.

## 구현하며 드러난 한계 (2026-09-01 추가)

설계대로 만들고 실기 검증까지 마친 뒤 남은 것들이다. 결함이 아니라 이 설계가
받아들인 대가이므로, 다음에 손댈 사람이 같은 곳을 다시 파지 않도록 적어 둔다.

### 근거 없는 TM 자료는 후보가 10개까지 나온다

`.prj`도 `crs` 멤버도 `srs_id`도 없는 순수 TM 좌표에서는 후보가 8~10개 남는다.
표본을 2점에서 전국 5점으로 늘려도, 상한 20점을 다 채워도 줄지 않는다 —
병목은 표본 수가 아니라 한국 영역 상자(경도 8°×위도 10°)가 중부·동부·서부·동해
원점(중심경선 2~4° 간격) × GRS80·Bessel 두 데이텀을 가르기엔 느슨하다는 점이다.

상자를 좁히면 백령도(124.6°E)와 독도(131.9°E)가 잘려 나가므로 간단히 조일 수 없다.
좌표만으로는 원리상 갈릴 수 없는 것이 맞고, 그래서 미리보기로 위치를 보여주는 것이다.
목록이 길다는 문제는 남는다. 줄이려면 판정이 아니라 **표시**를 바꿔야 한다 —
원점별로 묶어 접거나, 좌표 대신 지명을 보여주거나(`GeocodingService`가 이미 있다).

### DEM은 확인 창을 띄우지 않는다

픽셀을 재투영하지 않고 bbox만 변환하는 구조라 미리보기로 그릴 것이 없다.
`ambiguous`일 때 첫 후보를 쓰고 `console.warn`만 남긴다. 로더가 UI를 모르는 경계를
지키느라 상태 표시줄에도 알리지 않는다. DEM에 확인 창을 붙이려면 bbox를 폴리곤으로
만들어 미리보기 재료로 넘기는 방법이 있다.

### Shapefile 부분 취소 안내는 근사치다

여러 shapefile을 한 번에 넣고 그중 일부만 취소한 경우, `main.js`가 `.shp` 파일
basename 수로 "시도한 세트 수"를 세어 비교한다. 하나의 `.shp`가 여러 레이어로
펼쳐지는 드문 경우에는 "일부 취소됨" 안내가 뜨지 않는다. 정확히 세려면
`ShapefileLoader.loadFromFiles`의 반환 형태를 바꿔야 하고 `BrowserPanel`까지 파급된다.
머릿수(`ids.length`)는 언제나 정확하므로 거짓 성공 표시는 나지 않는다.

### 명시적 근거의 모순은 한국 자료에서만 잡힌다

`.prj`가 실제 좌표와 모순될 때, 선언된 좌표계가 한국 밖에 떨어지고 **다른 후보가
한국 안에 떨어질 때만** 확정을 낮춰 사용자에게 묻는다. 해외 자료를 오작동시키지
않으려는 대가로, 해외 자료끼리의 모순은 잡지 못한다.
