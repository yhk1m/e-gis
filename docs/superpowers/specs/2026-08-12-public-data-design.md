# 공공데이터 기능 설계

작성일: 2026-08-12
상태: 설계 확정 (구현 전)

## 무엇을 만드는가

공공데이터포털(data.go.kr)의 데이터를 e-GIS 안에서 바로 불러와 **포인트 · 격자 · 히트맵** 세 가지 레이어로 볼 수 있게 한다.

학생은 아무 준비(회원가입·키 발급) 없이 목록에서 고르기만 하면 된다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 데이터 출처 | 공공데이터포털(data.go.kr)만 | 전국 단위 API가 가장 많고 https·CORS가 열려 있다 |
| 서비스키 보관 | Vercel 서버리스 함수(환경변수) | 브라우저 번들에 키가 노출되면 하루 할당량을 남이 소진할 수 있다 |
| 데이터 선택 | 카탈로그(교사가 미리 등록) | 공공데이터포털은 API마다 응답 형식·좌표 필드가 제각각이라, 범용 처리는 학생이 쓰기 어렵다 |
| 중계 범위 | 카탈로그에 등록된 API만 | 임의 주소를 중계하면 키를 숨긴 의미가 사라진다 |
| 격자 집계 | 공공데이터 화면 안에서만 | 사용자 결정. 집계 로직은 독립 모듈로 두어 나중에 노출만 하면 되게 한다 |
| 메뉴 위치 | `데이터 불러오기` 다이얼로그의 네 번째 탭 `🌐 공공데이터` | 기존 세 탭(기본·스프레드시트·실습)과 같은 층위이고 학생 동선이 이미 그쪽이다 |

## 사전 측정 (2026-08-12)

설계의 전제가 된 실측 결과다. 추측이 아니다.

| 출처 | https | CORS 응답 헤더 | 브라우저 직접 호출 |
|---|---|---|---|
| `apis.data.go.kr` | 지원 | `Access-Control-Allow-Origin`에 요청 도메인을 그대로 echo | 가능해 보임 |
| `openapi.seoul.go.kr:8088` | **미지원** (443·8088 모두 연결 실패) | `*` | **불가** (https 페이지에서 http 호출은 차단됨) |

- data.go.kr 측정은 잘못된 키로 받은 403 응답 기준이다. **유효 키로 받은 성공 응답에도 같은 헤더가 붙는지는 실제 키로 재확인해야 한다.** 게이트웨이가 찍는 헤더로 보여 유지될 가능성이 높다.
- 서울시처럼 https를 안 여는 기관이 있으므로, 중계 함수를 두면 나중에 출처를 넓힐 때도 코드 구조를 바꾸지 않아도 된다.

## 구성 요소

| 구성 | 위치 | 성격 |
|---|---|---|
| 중계 함수 | `api/pubdata.js` (신규) | 키 보관 · 호출 · 응답 정규화 · 캐시 |
| 카탈로그 | `api/_catalog.js` (신규, **서버 전용**) | 등록된 API 정의. 엔드포인트·좌표 필드 매핑은 브라우저로 보내지 않는다 |
| 탭 내용 | `src/ui/dialogs/publicDataTab.js` (신규) | 목록·파라미터 폼·미리보기·레이어 생성 버튼 |
| 탭 자리 | `src/ui/dialogs/BuiltinDataDialog.js` (수정) | 탭 버튼 한 줄과 컨테이너만 추가 |
| 격자 집계 | `src/tools/gridAggregate.js` (신규, 순수 함수) | 포인트 배열 → 격자 폴리곤 + 집계값 |
| 포인트·히트맵 | 기존 재사용 | `layerManager.addLayer` / `heatmapTool.createHeatmap` |

`BuiltinDataDialog.js`는 이미 1,056줄이다. 탭 내용을 이 파일에 직접 넣지 않고 별도 모듈로 분리한다.

## 중계 함수 계약

```
GET /api/pubdata?list=1              → 목록 (id, 이름, 설명, 선택지 정의)
GET /api/pubdata?id=air-sido&sido=서울  → 정규화된 데이터
```

응답은 어떤 API를 쓰든 항상 같은 모양이다:

```json
{
  "items": [
    { "lon": 127.02, "lat": 37.51, "props": { "측정소": "강남구", "PM10": 42 } }
  ],
  "count": 25,
  "skipped": 2,
  "fetchedAt": "2026-08-12T01:00:00Z"
}
```

좌표 필드 이름 차이, XML/JSON 차이, 중첩 구조 차이를 **전부 서버가 흡수**한다. 브라우저 쪽 코드는 이 한 가지 형식만 안다.

### 규칙

- **허용 목록**: 카탈로그에 없는 `id`는 400으로 거부한다. 파라미터도 카탈로그에 정의된 키·값만 통과시킨다.
- **캐시**: `Cache-Control: s-maxage=600, stale-while-revalidate=3600`. 한 반 30명이 같은 항목을 눌러도 원본 호출은 1회다. 할당량 방어의 핵심이다.
- **좌표 없는 항목**: 서버가 걸러내고 `skipped`로 개수만 알린다.
- **오류 번역**: 공공데이터포털의 오류(키 만료·트래픽 초과·서비스 점검)를 한국어 안내 문장으로 바꿔 전달한다. 수업 중에는 원인을 모르는 실패가 가장 곤란하다.
- **타임아웃**: 10초, 실패 시 1회 재시도.
- ⚠️ 이 저장소는 `package.json`에 `"type": "module"`이라 서버 함수는 ESM(`export default`)으로 작성해야 한다. CommonJS로 쓰면 500이 난다.

## 카탈로그

### 항목 형식

```js
{
  id: 'air-sido',
  name: '대기오염 측정소 (실시간)',
  description: '시도별 미세먼지 등 실시간 측정값',
  endpoint: 'https://apis.data.go.kr/...',
  params: [{ key: 'sido', label: '시도', type: 'select', options: ['서울', '부산', ...] }],
  fixed: { returnType: 'json', numOfRows: 1000 },
  path: 'response.body.items',   // 배열이 있는 위치
  lon: 'dmX', lat: 'dmY',        // 좌표 필드
  epsg: 4326,                    // 좌표계. TM 좌표(5186 등)로 주는 API도 있다
  label: 'stationName',          // 이름으로 쓸 필드
  numeric: ['pm10Value', 'pm25Value']  // 격자 집계·히트맵 가중치 후보
}
```

좌표계 변환은 **서버가 하지 않는다.** 서버는 `epsg`를 그대로 실어 보내고, 변환은 브라우저에서 proj4로 한다(e-GIS에 이미 들어 있고 한국 좌표계 정의도 있다). 서버 함수를 가볍게 유지하기 위해서다.

### 등록 기준 (이 기능의 한계선)

- 응답에 **위경도가 있을 것**. 주소만 있는 데이터는 지오코딩이 필요해 이번 범위 밖이다.
- https 지원, JSON 응답 가능.
- 한 번에 수백~수천 건을 받을 수 있을 것.

## 화면 흐름

```
데이터 불러오기 → 🌐 공공데이터
  ▸ 목록에서 선택 → 시도 등 선택 → [불러오기]
  → 미리보기: "1,204건 (좌표 없는 2건 제외)" + 상위 5행 표
  → [포인트로 추가]  [격자 집계]  [히트맵]
                        ↓
                  격자 크기: 500m / 1km / 5km
                  집계: 개수 / 합계 / 평균 (+ 필드 선택)
```

세 버튼은 각각 **레이어 하나**를 만든다.

- **포인트로 추가** — 포인트 레이어 1개
- **격자 집계** — 포인트를 거치지 않고 격자 폴리곤 레이어 1개만 만든다(중간 포인트 레이어를 남기지 않는다)
- **히트맵** — 기존 `heatmapTool.createHeatmap(layerId, { hideSource: true })` 규약을 따른다. 포인트 레이어를 만든 뒤 히트맵을 얹고 원본은 숨긴다

같은 데이터를 두 가지로 보고 싶으면 버튼을 두 번 누르면 된다(각각 별개 레이어가 된다).

## 격자 집계 규칙

- EPSG:3857 정사각 격자. **데이터 범위 기준**으로 만든다(화면 범위 기준이면 지도를 움직일 때마다 결과가 바뀐다).
- 칸 배정은 `floor((x - minX) / cell)`. 빈 칸은 만들지 않는다(폴리곤 수 폭발 방지).
- 결과는 폴리곤 레이어에 `_choroplethConfig`를 붙여 **기존 단계구분도의 색·범례·저장 규약을 그대로 재사용**한다.
- 격자가 20,000칸을 넘으면 경고하고 셀 크기 조정을 유도한다.

## 테스트

- **정규화**(원본 응답 → `items`)와 **격자 집계**를 순수 함수로 분리해 vitest로 덮는다. 샘플 응답을 픽스처로 넣어 두면 API가 안 살아 있어도 회귀 검증이 된다.
- 서버 함수는 로컬 `vercel dev`로 확인한다.
- 기존 규약(단계구분도 스타일·저장/복원)을 건드리므로 전체 스위트를 돌린다.

## 이번 범위 밖

- 주소만 있는 데이터의 지오코딩
- 카탈로그 편집 UI (카탈로그는 코드로 관리하고 배포로 반영한다)
- 자동 갱신 / 실시간 폴링
- 학생별 키 입력
- 격자 집계를 벡터 분석 메뉴에 노출하는 것 (모듈은 독립적으로 두되 이번엔 공공데이터 화면에서만 부른다)

## 착수 전 준비물

구현을 시작하려면 아래가 필요하다. 코드만으로는 채울 수 없는 부분이다.

1. **공공데이터포털 서비스키** — 활용신청 후 발급. Vercel 환경변수(`DATA_GO_KR_KEY`)에 등록한다.
2. **첫 카탈로그 항목 1~2개** — 등록 기준(위경도 포함, https, JSON)을 만족하는지 실제 키로 응답을 한 번 받아 확인한다. 하나만 확인되면 나머지는 같은 틀로 늘리면 된다.

## 나중에 볼 것

- 유효 키로 받은 성공 응답에도 CORS 헤더가 붙는지 확인한다. 붙는다면 일부 항목은 중계 없이 직접 호출로 최적화할 여지가 있다(지금은 하지 않는다 — 키 보호가 우선).
- 격자 집계를 벡터 분석 메뉴에 노출할지. 모듈은 독립적이라 노출만 하면 된다.
