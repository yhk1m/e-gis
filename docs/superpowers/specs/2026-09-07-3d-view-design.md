# 지형·건물 3D 보기 설계

작성일: 2026-09-07
상태: 설계 확정

## 무엇을 만드는가

지도 영역을 2D와 3D로 토글한다. 3D로 바꾸면 **지금 화면에 보이는 그대로**가 입체로 선다.
지형은 불러온 DEM에서, 표면 무늬는 현재 2D 지도 화면에서, 건물은 폴리곤을 높이만큼 돌출시켜 만든다.

학생에게 설명할 규칙이 한 문장이다 — "평면에서 보이면 입체에서도 보인다."
단계구분도든 도형표현도든 격자든, 2D에서 만든 것이 그대로 지형 위에 얹힌다.

## 지금 상태

3D에 필요한 값은 **이미 대부분 메모리에 있다**. 새로 받아올 데이터가 없다.

| 자산 | 현재 | 3D에서의 쓰임 |
|---|---|---|
| `DEMLoader` | `demData = { data, width, height, extent, minVal, maxVal, noDataValue }`를 `layerInfo.demData`에 보관 | 지형 메시 원본. 그대로 읽는다 |
| `MapManager` / OpenLayers 9 | 2D 전용. 3D 기능 없음 | 뷰(중심·해상도·회전)의 유일한 기준점으로 계속 쓴다 |
| `ExportTool` | `html2canvas`로 지도 캡처 | **3D 텍스처로는 부적합**. 매 이동마다 갱신해야 해서 속도가 요건이다 |
| `LayerManager` | 레이어·스타일·가시성 관리 | 읽기만 한다. 고치지 않는다 |
| 공공데이터 탭 (`api/_normalize.js`) | `{ lon, lat, props }` — **포인트 전용** | 건물(폴리곤)은 여기로 못 들어온다. 아래 「건물 데이터 출처」 참조 |
| 실습 데이터 (`practice_catalog.json`) | 손으로 편집하는 카탈로그, `spatial` 유형 지원 | 건물 GeoJSON을 여기에 등록한다 |

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 렌더러 | **three.js를 더한다. OpenLayers는 그대로 둔다** | MapLibre/Cesium은 지도 엔진이 둘이 되어 레이어·스타일·가시성·저장을 양쪽에 동기화해야 한다. 용량보다 그 복잡도가 비싸다 |
| 배치 | `#map` 위를 덮는 오버레이 캔버스 + 토글 버튼 | 레이어 패널·범례·조작법이 그대로 남는다. 아래 2D 지도는 DOM에 살아 있어 계속 렌더된다(가려질 뿐) |
| 표면 무늬 | OL의 `.ol-layer canvas`들을 **직접 합성** | `html2canvas`는 DOM을 훑어 느리다. 캔버스 합성은 `drawImage` 몇 번이라 매 이동마다 돌려도 된다 |
| 정합 | 메시 범위 = 텍스처 범위 = **현재 화면 범위** | 셋이 같으므로 UV 매핑이 자동으로 맞는다. 재투영·리샘플링이 필요 없다 |
| 내비게이션 | **연동** — 3D에서 돌리고 옮기면 아래 OL 뷰가 따라 움직이고 텍스처를 다시 뽑는다(150ms 스로틀) | 2D↔3D 토글의 은유가 성립한다. 3D에서 옮긴 자리로 2D가 돌아온다 |
| 세로 과장 | 기본 **2배**, 슬라이더 1~10배 | 1:1이면 한국 산지가 밋밋해 수업에서 안 보인다 |
| 건물 | 폴리곤 + 높이 필드 → **병합 지오메트리 1개**(드로우콜 1회), 상한 3만 동 | 건물마다 메시를 만들면 드로우콜이 폭발한다 |
| 건물 데이터 출처 | 실습 데이터로 먼저. 공공데이터 탭 폴리곤 확장은 **사용자가 요청할 때 별건** | 아래 「건물 데이터 출처」 |
| 로딩 | `import('three')` 동적 로딩 | 3D를 켜지 않는 사용자 비용이 0이다 |
| 3D에서 편집·선택·측정 | 하지 않는다 | 범위 밖 |

## 모듈 구성

신규 `src/view3d/`. 계산은 순수 함수로 빼서 WebGL 없이 vitest로 검증한다.

```
View3DController        조립부 — LayerManager·MapManager를 아는 유일한 곳
  ├─ Scene3D            three 씬·카메라·렌더러·컨트롤 수명주기 (e-GIS를 모름)
  ├─ terrainMesh        demData → 정점 배열        (three·DOM 모름 · 순수)
  ├─ mapTexture         OL 캔버스들 → 캔버스 1장
  ├─ buildingMesh       폴리곤+높이 → 정점 배열     (three·DOM 모름 · 순수)
  └─ vectorOverlay3d    선 드레이프 · 점 기둥        (3단계)
ui/panels/View3DPanel   토글 · 과장 슬라이더 · 건물 설정 · PNG 저장
```

### terrainMesh.js

```js
buildTerrainGeometry({ demData, extent, maxGrid, exaggeration, latitude })
// → { positions: Float32Array, uvs: Float32Array, indices: Uint32Array,
//     gridWidth, gridHeight, holes }
```

`extent`(현재 화면 범위)와 DEM 범위의 교집합만 격자로 만든다.
`maxGrid`를 넘으면 자동으로 솎아낸다. `noDataValue` 픽셀은 삼각형에서 빼고 `holes`로 센다.

### buildingMesh.js

```js
buildBuildingGeometry({ features, heightField, levelsField, floorHeight,
                        defaultHeight, groundAt, maxCount })
// → { positions, normals, colors, indices, used, skipped }
```

`heightField`가 없으면 `levelsField × floorHeight`(기본 3m), 그것도 없으면 `defaultHeight`.
`groundAt(x, y)`는 지면 고도를 돌려주는 콜백이다 — DEM이 있으면 지형 위에, 없으면 0.
`maxCount`를 넘으면 화면 중앙에 가까운 것부터 채우고 나머지를 `skipped`로 센다.

**이 함수는 데이터가 어디서 왔는지 모른다.** 실습 데이터든, 사용자가 불러온 shp든,
나중에 공공데이터 탭이 폴리곤을 주게 되든 입력 모양이 같다. 출처를 바꿔도 3D 코드는 안 고친다.

### mapTexture.js

```js
composeMapCanvas(mapElement, { maxSize })
// → HTMLCanvasElement
```

`.ol-layer canvas`를 DOM 순서대로 한 캔버스에 겹쳐 그린다. 각 캔버스의 `transform`을 반영한다
(OL이 애니메이션 중에 캔버스를 변형해 두기 때문에 이걸 무시하면 텍스처가 어긋난다).
`maxSize`(2048)를 넘으면 줄인다.

## 데이터 흐름

3D 버튼을 누른 순간:

1. `import('three')` — 처음 한 번만 내려받는다
2. `map.renderSync()` → `composeMapCanvas()` → `THREE.CanvasTexture`
3. 보이는 DEM 레이어의 `demData`에서 현재 화면 범위를 잘라 `buildTerrainGeometry()`
4. 건물 레이어가 지정돼 있으면 `buildBuildingGeometry()`
5. 카메라를 45° 기울여 진입
6. 좌드래그 = 회전, 우드래그 = 이동, 휠 = 줌

연동 루프(3D를 조작할 때):

```
조작 중 (150ms 스로틀)
  카메라 이동 → 화면 중심·범위를 3857로 환산 → OL view.setCenter/setResolution
             → map.renderSync() → composeMapCanvas() → 텍스처만 교체

손을 뗀 뒤 (한 번)
  메시 재생성 — 새 화면 범위로 지형 격자를 다시 만들고 건물을 다시 추린다
```

조작 중에는 텍스처만 갈아 끼우고 메시는 그대로 둔다. 격자 재생성은 스로틀에 넣기엔 무겁고,
움직이는 동안에는 가장자리가 조금 어긋나도 눈에 띄지 않는다.

## 좌표와 단위

- 씬 좌표는 **EPSG:3857 미터에서 화면 중심을 뺀 값**을 쓴다. 3857 값이 1e7 규모라 float32에
  그대로 넣으면 정점이 떨린다(z-fighting·지터).
- 고도는 실제 미터다. 그런데 EPSG:3857의 가로 1단위는 위도 φ에서 실제 `cos φ` 미터다.
  비율을 맞추려면 **고도를 `1 / cos φ`배** 해야 한다. 서울(37.5°)에서 1.26배 —
  무시하면 지형이 26% 납작해진다.
- 최종 z = `고도 × (1 / cos φ) × 세로과장`.

## 성능 예산

상한을 코드에 박는다. 넘으면 죽지 말고 줄인다.

| 항목 | 기본 | 상한 | 초과 시 |
|---|---|---|---|
| 지형 격자 | 화면에 맞춰 자동(~256²) | 512×512 (삼각형 52만) | 자동 솎아내기 |
| 텍스처 | 화면 크기 | 2048×2048 | 축소 |
| 건물 | — | 3만 동 | 화면 중앙 우선, 나머지 경고 |
| 건물 드로우콜 | — | 1 | 병합 지오메트리 |
| 텍스처 재캡처 | 150ms 스로틀 | — | — |
| 3D 미사용자 | **0KB · 0ms** | — | 동적 import |

## 예외 처리

| 상황 | 동작 |
|---|---|
| WebGL 미지원 | 3D 버튼 비활성 + 안내. 2D는 그대로 |
| DEM 레이어 없음 | 평면 바닥 위에 텍스처. 건물만 볼 때 정상 동작 |
| DEM이 화면 밖 | 평면 바닥으로 처리 |
| 높이 필드 없음 | 필드 선택 대화상자에서 기본 높이를 입력받는다 |
| 건물 3만 동 초과 | "3만 동까지 표시합니다" 경고. 죽지 않는다 |
| 컨텍스트 손실 | 씬을 버리고 2D로 되돌린 뒤 안내 |

## 건물 데이터 출처

GIS건물통합정보는 국가공간정보포털의 **시군구 단위 shp 파일**이다. 공공데이터 탭은
`api/_catalog.js`에 "위경도가 있을 것 · JSON일 것 · 한 번에 수천 건"이라는 등록 기준이 있고
`_normalize.js`가 포인트만 뱉는다. 폴리곤·대용량은 지금 파이프라인에 들어가지 않는다.

**1단계 채택**: 수업할 지역을 GeoJSON으로 가공해 실습 데이터에 등록한다.
높이·층수·용도 필드만 남기고 좌표 정밀도를 줄인다(자치구 1개 대략 gzip 2~5MB).
사용자가 shp를 직접 불러오는 경로도 지금 그대로 동작한다.

**후속(사용자 요청 시)**: 공공데이터 탭을 폴리곤·대용량까지 확장한다.
`buildingMesh`가 출처를 모르므로 그때 3D 코드는 고치지 않는다.

## 테스트

순수 함수는 vitest로, 렌더는 실측으로 나눈다.

| 대상 | 방법 |
|---|---|
| `terrainMesh` | 솎아내기 후 정점 수, `noData` 구멍, 화면 범위 클리핑, 과장·위도 보정 반영 |
| `buildingMesh` | 높이 필드 우선순위, 층수×층고 환산, 상한 초과 시 `skipped`, 지면 고도 샘플링 |
| `mapTexture` | 캔버스 합성 순서, `transform` 반영, 크기 상한 |
| WebGL 렌더 | 단위테스트하지 않는다. `vite preview` + Electron 실측 하네스로 확인한다 |

## 단계

각 단계가 끝나면 그 자체로 수업에 쓸 수 있다.

**1단계 — 지형과 주제도**
토글 버튼, 지형 메시, 텍스처 드레이프, 연동 내비게이션, 세로 과장 슬라이더, 3D 화면 PNG 저장.

**2단계 — 건물 돌출**
폴리곤 레이어 + 높이 필드 선택, 병합 지오메트리, 높이별 색칠, 지면 고도 위 배치.
실습 데이터에 건물 GeoJSON 등록.

**3단계 — 3D 벡터**
선 레이어를 지형에 드레이프(등고선·하천), 점 레이어를 속성값 기둥으로.

## 범위 밖

- 3D 화면에서의 편집·선택·측정
- 스토리맵·발표 슬라이드에 3D 장면 넣기
- 브이월드 실사 3D 건물, Cesium
- 공공데이터 탭 폴리곤 확장 — 사용자가 요청할 때 별건
- `.egis` 프로젝트에 3D 설정(과장·카메라) 저장 — 1단계를 써 본 뒤 판단한다
