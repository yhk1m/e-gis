# 피처 합치기 되돌리기 설계

작성일: 2026-08-26
상태: 설계 확정

## 무엇을 고치는가

합치기는 지금 되돌릴 수 없다. 같은 레이어 병합은 **원본 피처를 지우는데** 되돌리기가
안 들어서 복구할 방법이 없다. 열려 있던 속성 테이블은 지워진 행을 계속 보여주고,
레이어 목록의 피처 개수 배지도 옛 숫자 그대로다.

원인: `HistoryManager` 는 `FEATURE_CREATED` · `FEATURE_DELETED` · `FEATURE_MODIFY_START` +
`FEATURE_MODIFIED` 만 듣는다 (`HistoryManager.js:23-64`). 합치기는 `FEATURE_MODIFIED` 만
쏘는데 앞선 `MODIFY_START` 가 없어 리스너가 그냥 빠져나간다. 즉 아무것도 기록되지 않는다.
소스의 `addfeature`/`removefeature` 를 듣는 곳도 저장소 전체에 없다.

## 왜 한 번에 되돌려야 하는가

가장 손쉬운 고침은 `FEATURE_CREATED` 하나와 `FEATURE_DELETED` 를 원본 수만큼 쏘는 것이다.
그러면 기록은 남지만 **되돌리기가 N+1 번으로 쪼개진다.**

그 중간 상태가 문제다. 합친 폴리곤이 남아 있는데 원본이 하나씩 되살아나면
**같은 자리에 겹친 도형이 있는 지도**가 된다. 지리적으로 말이 안 되는 화면이고,
수업 중에 보면 프로그램이 고장 난 것처럼 보인다.

합치기는 사용자에게 **한 동작**이다. 되돌리기도 한 번이어야 한다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 되돌리기 단위 | 합치기 한 번 = 액션 한 개 | 중간 상태(겹친 도형)를 만들지 않는다 |
| 새 이벤트 | `Events.FEATURES_MERGED` | 기존 이벤트로는 '여러 개가 하나가 되었다'를 표현할 수 없다 |
| 같은 레이어 되돌리기 | 합친 피처를 빼고 원본을 전부 되살린다 | 원본이 지워지는 유일한 경로 — 여기가 핵심이다 |
| 다른 레이어 되돌리기 | **새로 만든 레이어를 통째로 지운다** | 원본은 애초에 손대지 않았으니 지울 것이 그것뿐이다 |
| 다시 실행 | 둘 다 대칭으로 되돌린다 | Ctrl+Shift+Z 가 이미 있다 (`main.js:159`) |
| 되살린 피처의 `ol_uid` | 원래 값으로 복원 | 기존 `delete` 되돌리기가 쓰는 방식과 같다 (`HistoryManager.js:158`) |
| 되살릴 때 레이어 유지 | 피처가 0개를 거쳐도 레이어를 지우지 않는다 | `create` 되돌리기는 0개가 되면 레이어를 지운다(`:148-151`). 병합 되돌리기는 곧 원본을 채우므로 그 규칙을 타면 안 된다 |
| 다시 만든 레이어의 색 | 액션에 이름·색을 담아 그대로 되살린다 | 색을 안 담으면 자동 색이 잡혀 흰색이 나올 수 있다 (2026-08-25 설계의 「새 레이어 색」 참고) |

## 동작

| 상황 | 되돌리기 | 다시 실행 |
|---|---|---|
| 같은 레이어에서 합침 | 합친 피처 제거 + 원본 전부 복원 | 원본 제거 + 합친 피처 복원 |
| 다른 레이어끼리 합침 | 새 레이어 제거 (원본은 원래 그대로였다) | 같은 이름·색으로 레이어를 다시 만든다 |

## 함께 고쳐지는 것

- **속성 테이블**: `FEATURES_MERGED` 를 듣게 해서 합친 직후·되돌린 직후 모두 갱신한다.
  지금은 지워진 행이 그대로 남아 있다.
- **레이어 목록 배지**: 같은 이벤트로 다시 그린다. 지금은 피처 개수가 옛 숫자다.

## 구성 요소

| 구성 | 위치 | 성격 |
|---|---|---|
| `Events.FEATURES_MERGED` | `src/utils/EventBus.js` | 새 이벤트 이름 |
| 병합 액션 기록·되돌리기·다시 실행 | `src/core/HistoryManager.js` | `merge` 액션 타입 추가 |
| 이벤트 발행 | `src/tools/FeatureEditTool.js` | 두 경로에서 각각 발행 |
| 표 갱신 | `src/ui/panels/AttributeTable.js` | 리스너 한 줄 |
| 목록 갱신 | `src/ui/panels/LayerPanel.js` | 리스너 한 줄 |

`FeatureEditTool` 이 지금 쏘는 `FEATURE_MODIFIED` 는 이 경로에서 **아무도 듣지 않는다**
(유일한 리스너인 `HistoryManager` 가 `pendingModify` 없이 빠져나간다). `FEATURES_MERGED` 로 바꾼다.

## 테스트

`src/core/HistoryManager.merge.test.js` 를 새로 만든다.
`src/core/` 에는 이미 `// @vitest-environment jsdom` + 실제 `layerManager` 싱글톤으로 도는
테스트가 있다 (`LayerManager.polygonDefaults.test.js`). 같은 방식을 따른다.

| 확인할 것 |
|---|
| 같은 레이어 병합을 되돌리면 원본 2개가 도형·속성 그대로 살아난다 |
| 그때 합친 피처는 사라진다 |
| 되돌리기 한 번이면 된다 (액션이 1개만 쌓인다) |
| 되돌린 뒤 레이어가 사라지지 않는다 |
| 다시 실행하면 합친 상태로 정확히 돌아간다 |
| 다른 레이어 병합을 되돌리면 새 레이어만 사라지고 원본 레이어는 그대로다 |
| 그것을 다시 실행하면 같은 이름·색으로 레이어가 되살아난다 |

실기 확인은 `Desktop/vibecoding/eGIS:verify` 스킬의 Electron 하네스로 한다 —
합치기 버튼을 누른 뒤 실제 Ctrl+Z 경로(`historyManager.undo()`)를 태운다.

## 하지 않는 것

- 되돌리기 스택을 프로젝트에 저장하는 것 (지금도 세션 한정이다)
- `FEATURE_MODIFIED` 가 `MODIFY_START` 없이 무시되는 구조 자체를 손보는 것
- 주제도(단계구분도·카토그램) 분류를 병합 후 다시 계산하는 것 — 별개 문제다
