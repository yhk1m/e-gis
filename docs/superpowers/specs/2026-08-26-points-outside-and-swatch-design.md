# 1. 폴리곤 밖 포인트 추출

## 무엇을 만드는가

`공간 연산 ▸ 포인트 추출` 은 지금 폴리곤 **안**의 포인트만 남긴다.
**밖**의 포인트도 뽑을 수 있게 한다.

수업에서 "이 권역에 속하지 않는 관측소" 처럼 여집합을 묻는 일이 안쪽만큼 흔하다.
지금은 안쪽을 뽑아 놓고 원본과 눈으로 비교하는 수밖에 없다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| UI | 「포인트 추출」 안에 **폴리곤 안 / 폴리곤 밖** 라디오 | 안과 밖은 같은 개념의 양면이다. 한 자리에서 비교되고 연산 목록도 짧게 유지된다. 패널에 이미 옵션 자리가 마련돼 있다 |
| 구현 | 기존 `pointsInPolygons` 에 모드를 더한다 (함수를 쪼개지 않는다) | **여집합이 정확히 `!inside`** 라야 한다. 판정을 한 곳에서만 하면 경계 위의 점이 양쪽에 다 들어가거나 어디에도 안 들어가는 일이 구조적으로 불가능해진다 |
| 밖 결과의 속성 | 원본 속성 그대로, `poly_` 태그 **없음** | 담고 있는 폴리곤이 없으니 태그할 것이 없다 |
| MultiPoint | 지금 규약(한 점이라도 들어가면 포함)을 그대로 뒤집는다 | 같은 판정을 부정할 뿐이다 |
| 결과 레이어 이름 | `_폴리곤내` ↔ `_폴리곤밖` | 지금 규칙의 대칭 |
| 아무것도 안 남을 때 | 지금처럼 오류로 알린다 (문구만 모드에 맞게) | 빈 레이어를 만들어 두면 왜 비었는지 알 수 없다 |

## 동작

| 상황 | 안 | 밖 |
|---|---|---|
| 어떤 폴리곤에도 안 들어간 포인트 | 버린다 | **남긴다** |
| 폴리곤에 들어간 포인트 | 남기고 `poly_*` 태그 | 버린다 |
| 경계 위의 점 | `turf.booleanPointInPolygon` 판정을 따른다 | 그 판정의 여집합 |

안과 밖의 개수 합은 항상 전체 포인트 수와 같다. 이것이 이 설계의 핵심 성질이다.

## 테스트

`src/tools/SpatialOperationsTool.test.js` 에 더한다.

| 확인할 것 |
|---|
| 밖 모드는 폴리곤에 안 들어간 포인트만 남긴다 |
| 밖 결과에는 `poly_` 속성이 붙지 않고 원본 속성은 그대로다 |
| 안 개수 + 밖 개수 = 전체 포인트 수 (경계 위 점을 포함해서) |
| 전부 폴리곤 안에 있으면 밖 모드는 오류로 알린다 |
| 안 모드 결과는 예전과 같다 (회귀 방지) |

# 2. 레이어 스와치를 도형 종류대로

## 무엇을 고치는가

레이어 목록의 색 표시가 지도와 어긋난다. 모양이 늘 사각형인 것뿐 아니라
테두리도 안 맞는다. 스와치가 지도 스타일과 **별개 로직**으로 그려지기 때문이다.

| 레이어 | 지도에 그려지는 것 | 지금 스와치 |
|---|---|---|
| 포인트 | 원, 채움=색, 테두리 **흰색** | 사각형, 테두리 **색** |
| 라인 | 선만 (굵기 3) | **꽉 찬 사각형** |
| 폴리곤 | 채움=색+투명도, 테두리 **검정**(검은 면이면 흰색) | 채움=색(투명도 없음), 테두리 **색** |

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 모양 | 포인트=원, 라인=선, 폴리곤=면 | QGIS 와 같다. 목록만 봐도 무엇을 다루는 레이어인지 안다 |
| 파생 | **`createStyle` 과 같은 기본값**을 쓰는 순수 모듈에서 계산 | 어긋남의 원인이 두 벌의 로직이었다. 값이 한 곳에서 나와야 다시 어긋나지 않는다 |
| 그리기 | 인라인 SVG | 선과 점선을 CSS 로 흉내 내는 것보다 정직하다 |
| 색 바꿀 때 갱신 | `refreshSwatch(layerId)` 하나로 모은다 | 지금은 `.layer-color` 의 `backgroundColor`/`borderColor` 를 직접 찌르는 곳이 여덟 군데다 |
| 주제도 레이어 | 단계구분도·히트맵·카토그램·래스터는 **지금처럼 단색** | 요청 범위 밖이다. 색 띠는 범례 로직과 얽혀 따로 다뤄야 한다 |

## 구성 요소

| 구성 | 위치 | 성격 |
|---|---|---|
| `swatchSpec(layerInfo)` | `src/ui/panels/layerSwatch.js` (신규) | 순수 함수. `{shape, fill, stroke, fillOpacity, strokeWidth, dash}` |
| `swatchHTML(spec)` | 같은 파일 | 순수 함수. 인라인 SVG 문자열 |
| 렌더·갱신 | `src/ui/panels/LayerPanel.js` | 목록 렌더와 `refreshSwatch` |
| 크기·정렬 | `src/styles/panels.css` | `.layer-color` 규칙 조정 |

## 함정

클릭 핸들러가 `e.target.classList.contains('layer-color')` 로 스와치를 판정한다
(`LayerPanel.js:325`). SVG 를 넣으면 `e.target` 이 안쪽 `<circle>` 이 되어 **색 편집기가
안 열린다.** `closest('.layer-color')` 로 바꾼다. 이 회귀를 테스트로 막는다.

## 테스트

`src/ui/panels/layerSwatch.test.js` 를 새로 만든다.

| 확인할 것 |
|---|
| 포인트 레이어는 원, 테두리는 흰색 (지도와 같다) |
| 라인 레이어는 선, 굵기·점선이 반영된다 |
| 폴리곤 레이어는 면, 투명도와 검정 테두리가 반영된다 |
| 검은 폴리곤의 테두리는 흰색이다 (`defaultStrokeFor` 규약) |
| 사용자가 지정한 `fillColor`·`strokeColor` 가 자동값을 이긴다 |
| 주제도·래스터 레이어는 단색 사각형 그대로다 |
| SVG 안쪽 요소를 클릭해도 스와치로 판정된다 (색 편집기 회귀 방지) |

## 하지 않는 것

- 주제도 스와치에 색 띠 넣기
- 지도 스타일(`createStyle`)을 이 모듈로 옮기는 리팩터링 — 방향은 맞지만 이번 범위가 아니다
- 스와치에서 바로 스타일을 바꾸는 기능
