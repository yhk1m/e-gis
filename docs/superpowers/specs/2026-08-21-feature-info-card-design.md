# 선택 피처 속성 카드 설계

작성일: 2026-08-21
상태: 설계 확정 (구현 전)

## 무엇을 만드는가

선택 도구로 고른 피처의 속성을, **지도 위에 뜨는 카드**로 바로 보여준다.

지금은 속성을 보려면 속성테이블 패널을 열어야 하는데, 패널은 피처를 고르는 동안 최소화되거나 지도에 가려 실질적으로 같이 볼 수 없다. 카드는 범례·축척바와 같은 층위의 지도 오버레이라 그 문제가 없다.

여러 피처를 고르면 여러 개의 속성이 **한 카드 안에 동시에** 나열된다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 표시 형태 | 지도 위 독립 카드 1개 (범례 패턴) | 패널이 아니라 최소화·가려짐 문제가 없다. 사용자 선택 |
| 여러 개 선택 시 | 한 카드 안에 피처별 섹션을 쌓기 | 카드가 여러 개면 많이 고를수록 화면이 덮인다. 사용자 선택 |
| 필드가 많을 때 | 전부 표시하고 섹션 단위로 접기/펼치기 | 수업에서 볼 필드를 미리 알 수 없다. 잘라내면 매번 펼쳐야 한다. 사용자 선택 |
| 기본 위치 | 지도 좌측 상단 | 우측 상단은 줌·나침반·현위치·배경지도, 좌측 하단은 범례·축척바, 우측 하단은 도형표현도 범례·출처가 이미 쓴다. 좌측 상단만 비어 있다 |
| 버튼 위치 | 툴바 선택 그룹, 선택 버튼 바로 오른쪽 | 사용자 지정 |
| 다른 방식 | 채택하지 않음 | 속성테이블 필터 뷰는 패널이라 같은 문제가 남고 결합도만 오른다. OL Overlay 말풍선은 여러 개 선택 시 겹치고 지도 이동마다 흔들린다 |

## 동작 규칙

**버튼**

- 툴바 선택 그룹, 선택 버튼 오른쪽에 `#btn-feature-info` (ⓘ). 평소 `display:none`.
- `TOOL_ACTIVATED {tool:'select'}` → 버튼이 나타난다.
- `TOOL_DEACTIVATED {tool:'select'}` → 버튼이 사라지고 토글은 OFF로 되돌아간다.
- 토글이다. 켜면 `.active`, 다시 누르면 꺼진다.

**카드가 보이는 조건**

```
선택 도구 활성  AND  버튼 ON  AND  선택된 피처 1개 이상
```

셋 중 하나라도 어긋나면 카드는 DOM에서 제거된다.

| 상황 | 버튼 | 카드 |
|---|---|---|
| 버튼을 껐다 | OFF | 사라짐 |
| 선택 도구를 껐다 | 숨김 + OFF | 사라짐 |
| 선택을 모두 해제했다 (도구·버튼은 그대로) | ON 유지 | 사라짐. 다시 고르면 즉시 나타남 |
| 카드의 ✕ 를 눌렀다 | OFF | 사라짐 |
| 프로젝트를 새로 만들었다 (`PROJECT_NEW`) | 숨김 + OFF | 사라짐 |

**갱신**

- `SELECTION_CHANGED` 가 올 때마다 내용을 다시 그린다.
- 접어둔 섹션과 카드의 스크롤 위치는 다시 그려도 유지한다. 기준 키는 `feature.ol_uid`.
- 카드 우하단 손잡이를 끌어 크기를 조절한다. 손으로 정한 크기는 높이 60% 제한보다 우선하되 지도 밖으로는 넘어가지 않는다. 최소 180 x 120.
- 카드가 떠 있는 동안 선택이 바뀌면 카드를 다시 만들지 않고 내용만 교체한다. 드래그로 옮긴 위치가 그대로 남는다.
- 조건이 어긋나 카드가 사라졌다가 다시 뜰 때도, 마지막으로 옮긴 위치와 크기 그대로 다시 뜬다. 페이지가 열려 있는 동안 기억한다.

**섹션 제목(대표 이름) 결정 순서**

1. 그 레이어에 라벨 필드가 설정돼 있으면 그 필드의 값
2. 없으면 이름으로 흔히 쓰는 필드(`name`, `이름`, `NAME`, `시군구명` 등) 중 값이 있는 첫 필드
3. 없으면 값이 문자열인 첫 속성
4. 전부 없으면 `피처 N` (선택 순서 N)

**표시 규칙**

- `geometry` 속성은 제외한다.
- 값이 `null`·`undefined`·빈 문자열이면 `-` 로 적는다.
- 속성 순서는 원본 필드 순서를 그대로 따른다.
- 카드 높이가 지도 높이의 60%를 넘으면 카드 안에서 세로 스크롤한다.
- 레이어명은 섹션 제목 오른쪽에 배지로 붙인다. 서로 다른 레이어의 피처를 함께 골랐을 때 구분된다.

## 구성 요소

| 구성 | 위치 | 성격 |
|---|---|---|
| 속성 카드 모델 | `src/ui/featureInfoModel.js` (신규) | 순수 함수. 선택 피처 배열 → 섹션 데이터 배열. DOM·OL 의존 없음 |
| 속성 카드 | `src/ui/FeatureInfoCard.js` (신규) | 렌더·이벤트·표시 조건. 얇게 유지한다 |
| 툴바 버튼 | `src/ui/layout/AppLayout.js` | 마크업만 추가 |
| 배선 | `src/main.js` | 버튼 클릭 · 툴/선택 이벤트 → 카드 |
| 스타일 | `src/styles/main.css` | 범례 블록 옆에 `.feature-info-card` |

`legendModel.js` + `legendModel.test.js` 가 이미 쓰는 분리 방식을 그대로 따른다. 로직은 모델에 두고 테스트하며, 카드는 그린다.

### 모델 인터페이스

```js
// 선택된 피처들을 카드가 그릴 수 있는 형태로 바꾼다.
// features: ol/Feature[]  (선택 순서)
// deps: { findLayer(feature) -> {id, name}|null, getLabelField(layerId) -> string|null }
buildFeatureInfoSections(features, deps)
//  -> [{ key, title, layerName, attributes: [{ name, value }] }, ...]
```

`key` 는 `feature.ol_uid`. 카드는 이 키로 접힘 상태를 기억한다.

## 안전

- 속성값·레이어명·제목은 모두 `escapeHtml()` 을 거쳐 넣는다. 사용자가 불러온 데이터에 태그가 섞여 있어도 실행되지 않는다.

## 테스트

`src/ui/featureInfoModel.test.js`

- 대표 이름 결정 순서 네 갈래 (라벨 필드 → 이름 필드 → 첫 문자열 → `피처 N`)
- `geometry` 가 속성 목록에서 빠진다
- 빈 값(`null`/`undefined`/`''`)이 `-` 로 나온다
- 서로 다른 레이어의 피처를 섞어 골랐을 때 각 섹션에 제 레이어명이 붙는다
- 선택 0개면 빈 배열

기존 374개 테스트는 그대로 통과해야 한다.

## 하지 않는 것

- 카드에서 속성을 편집하는 기능. 편집은 속성테이블이 담당한다.
- 피처마다 카드를 따로 띄우는 방식.
- 카드 내용 내보내기·복사 기능.
