# 다른 레이어끼리 피처 합치기 설계

작성일: 2026-08-25
상태: 설계 확정

## 무엇을 바꾸는가

지금 `피처 합치기`는 **같은 레이어 안에서만** 된다. 다른 레이어의 폴리곤을 함께 고르면
"같은 레이어의 피처만 합칠 수 있습니다"로 거부한다.

이 검사를 없애고, **레이어를 넘나드는 합치기는 결과를 새 레이어로** 만든다.
원본 레이어는 건드리지 않는다.

행정구역을 두 레이어로 나눠 받아 온 뒤 하나의 권역으로 묶는 것 같은 수업 상황이
지금은 "레이어 합치기 → 피처 합치기" 두 단계를 거쳐야 되는데, 한 번에 끝나게 하려는 것이다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 같은 레이어 합치기 | **지금 그대로** — 제자리 병합, 원본 피처 제거 | 도형 정리 작업의 기존 흐름을 바꾸지 않는다 |
| 다른 레이어 합치기 | **원본은 그대로 두고 결과만 새 레이어** | 어느 레이어에 넣을지 모호한 경우만 새 레이어로 푼다. 잘못 합쳐도 되돌리기 쉽다 |
| 원본 처리 | 손대지 않는다 (선택지 없음) | 버퍼·오버레이·격자 만들기와 같은 규칙(입력 보존 + 결과 신규 레이어). 체크박스를 두면 확인 단계만 늘고 원본을 잃을 위험이 생긴다 |
| 속성 | **모든 피처의 필드를 합집합**으로 모은다 | 다른 레이어에만 있는 필드가 조용히 사라지지 않게 |
| 숫자 필드 | 합계 (지금 규칙 유지). 어떤 필드가 숫자인지는 **그 필드가 처음 등장한 피처의 값**으로 판단한다 | 인구·면적을 합쳐 병합 후 주제도를 만들 수 있어야 한다 |
| 그 외 필드 | 값이 있는 첫 피처의 값 | 지금 규칙의 자연스러운 확장 |
| 도형 종류 | 폴리곤·라인 모두 같은 규칙, 포인트는 거부 | 코드 경로가 하나다. 갈라놓으면 규칙만 복잡해진다 |
| 새 레이어 이름 | 2개면 `A + B 병합`, 3개 이상이면 `A 외 2개 병합` | 무엇을 합친 결과인지 목록에서 바로 보이게 |
| 새 레이어 색 | 지정하지 않고 자동 색에 맡긴다 | 원본이 남아 있는데 같은 색이면 지도에서 구분이 안 된다 |
| 합친 뒤 선택 | 선택 해제 | 원본이 그대로 남아 있어 "합쳐진 것"을 다시 선택해 두면 헷갈린다 |

## 동작

| 상황 | 결과 |
|---|---|
| 2개 미만 선택 | 지금처럼 안내하고 중단 |
| 포인트 포함 | 지금처럼 거부 |
| 폴리곤과 라인이 섞임 | 지금처럼 거부 |
| 한 레이어 안에서 선택 | 원본 피처를 빼고 합친 도형을 그 레이어에 넣는다 (**변경 없음**) |
| 두 개 이상 레이어에 걸쳐 선택 | 원본을 그대로 둔 채, 합친 도형 1개만 담은 벡터 레이어를 새로 추가한다 |

떨어져 있는 폴리곤을 합치면 `turf.union`이 MultiPolygon을 돌려준다. 지금과 같고, 따로 다루지 않는다.

합친 뒤 상태표시줄 문구:
`레이어 2개의 피처 3개를 합쳐 'A + B 병합'을 만들었습니다.`

## 구성 요소

| 구성 | 위치 | 성격 |
|---|---|---|
| `mergeAttributes` | `src/tools/FeatureEditGeometry.js` | 순수 함수. 첫 피처 기준 → **필드 합집합**으로 확장 |
| `mergedLayerName` | `src/tools/FeatureEditGeometry.js` (신규) | 순수 함수. 레이어 이름 배열 → 새 레이어 이름 |
| `mergeGeoJSON` | `src/tools/FeatureEditGeometry.js` | **변경 없음**. 레이어 개념이 없다 |
| `mergeSelected` | `src/tools/FeatureEditTool.js` | 레이어 검사 제거, 레이어 수로 분기 |
| 툴팁·도움말 | `src/ui/layout/AppLayout.js`, `src/main.js` | 다른 레이어끼리도 된다는 안내 |

지오메트리 연산과 이름 규칙은 OL/DOM 없이 GeoJSON in → out 으로만 돌아가는 순수 모듈에 둔다.
`mergeSelected`는 선택 읽기·레이어 만들기·안내만 맡는다. 지금 구조 그대로다.

## 속성 합치기 규칙

선택한 피처가 다음과 같을 때

| 피처 | 시군구 | 인구 | 면적 | 비고 |
|---|---|---|---|---|
| A (레이어 1) | 강남구 | 53만 | 39.5 | |
| B (레이어 2) | 서초구 | 41만 | | 관측소 |

결과는 `{ 시군구: '강남구', 인구: 94만, 면적: 39.5, 비고: '관측소' }`.

- 필드 순서는 처음 등장한 순서
- 숫자 필드는 합계 (없는 쪽은 0으로 친다 — 지금 규칙)
- 숫자가 아닌 필드는 값이 있는 첫 피처의 값. `null`·빈 문자열은 건너뛴다
- 같은 레이어끼리는 스키마가 같으므로 **필드 구성이 지금과 같다**. 값이 달라지는 경우는
  첫 피처의 값이 비어 있을 때뿐이고, 그때는 다음 피처의 값을 쓴다 (지금은 빈 값이 그대로 남는다).
  의도한 개선이다

## 테스트

`src/tools/FeatureEditGeometry.test.js` 를 새로 만든다 (이 모듈은 지금 테스트가 없다).

| 대상 | 확인할 것 |
|---|---|
| `mergeAttributes` | 숫자 필드 합계 |
| `mergeAttributes` | 한쪽에만 있는 필드가 남는다 |
| `mergeAttributes` | 빈 값을 건너뛰고 값이 있는 첫 피처의 값을 쓴다 |
| `mergeAttributes` | 같은 스키마 + 빈 값 없음 → 기존 결과와 같다 (회귀 방지) |
| `mergeAttributes` | 어떤 필드가 숫자인지는 그 필드가 처음 등장한 피처로 판단한다 |
| `mergedLayerName` | 2개일 때 `A + B 병합` |
| `mergedLayerName` | 3개 이상일 때 `A 외 2개 병합` |

`mergeSelected`의 레이어 분기는 OL 선택·`alert`에 얽혀 있어 단위 테스트 대상에서 뺀다.
브라우저에서 다음 세 가지를 직접 확인한다.

1. 같은 레이어 폴리곤 2개 → 제자리 병합 (기존과 동일)
2. 다른 레이어 폴리곤 2개 → 원본 2개 그대로, 새 레이어 1개 추가, 색이 원본과 다름
3. 다른 레이어 폴리곤 3개 (레이어 3개) → 이름이 `A 외 2개 병합`

## 하지 않는 것

- 원본 삭제 옵션 (체크박스·대화상자)
- 같은 레이어 합치기를 새 레이어 방식으로 바꾸는 것
- 포인트 합치기
- 병합 결과에 원본 레이어 이름을 기록하는 필드 — 피처가 1개로 합쳐지므로 담을 곳이 마땅치 않다
