# 다른 레이어끼리 피처 합치기 설계

작성일: 2026-08-25
상태: 설계 확정

## 무엇을 바꾸는가

지금 `피처 합치기`는 **같은 레이어 안에서만** 된다. 다른 레이어의 폴리곤을 함께 고르면
"같은 레이어의 피처만 합칠 수 있습니다"로 거부한다.

이 검사를 없애고, **레이어를 넘나드는 합치기는 결과를 새 레이어로** 만든다.
원본 레이어는 건드리지 않는다.

행정구역을 두 레이어로 나눠 받아 온 뒤 하나의 권역으로 묶는 것 같은 수업 상황이
지금은 "레이어 합치기 → 피처 합치기" 두 단계를 거쳐야 되는데, 한 번에 끝나게 하려는 것이다.

## 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 같은 레이어 합치기 | **지금 그대로** — 제자리 병합, 원본 피처 제거 | 도형 정리 작업의 기존 흐름을 바꾸지 않는다 |
| 다른 레이어 합치기 | **원본은 그대로 두고 결과만 새 레이어** | 어느 레이어에 넣을지 모호한 경우만 새 레이어로 푼다. 잘못 합쳐도 되돌리기 쉽다 |
| 원본 처리 | 손대지 않는다 (선택지 없음) | 버퍼·오버레이·격자 만들기와 같은 규칙(입력 보존 + 결과 신규 레이어). 체크박스를 두면 확인 단계만 늘고 원본을 잃을 위험이 생긴다 |
| 속성 | **모든 피처의 필드를 합집합**으로 모은다 | 다른 레이어에만 있는 필드가 조용히 사라지지 않게 |
| 숫자 필드 | 합계. 어떤 필드가 숫자인지는 **그 필드에 값이 처음 들어 있는 피처**로 판단하고, **유한한 `number` 만** 더한다 (`isSummable`). 숫자로 보이는 문자열(`'11110'`, `'2025'`)은 더하지 않는다 | 인구·면적은 합쳐야 주제도를 만들 수 있지만, 코드·연도가 더해지면 되돌릴 수 없다. 한때 `isNumericValue` 를 쓰기로 했다가 되돌렸다 — 아래 「수치 판별」 참고 |
| 그 외 필드 | 값이 있는 첫 피처의 값 | 지금 규칙의 자연스러운 확장 |
| 도형 종류 | 폴리곤·라인 모두 같은 규칙, 포인트는 거부 | 코드 경로가 하나다. 갈라놓으면 규칙만 복잡해진다 |
| 새 레이어 이름 | 2개면 `A + B 병합`, 3개 이상이면 `A 외 2개 병합` | 무엇을 합친 결과인지 목록에서 바로 보이게 |
| 새 레이어 색 | **쓰이지 않는 팔레트 색을 직접 고른다** (흰색 제외, 예비값 회색) | 원본이 남아 있는데 같은 색이면 지도에서 구분이 안 된다. 자동 색은 쓰이는 색을 보지 않아 프로젝트를 다시 열면 흰색이 나온다 — 아래 「새 레이어 색」 참고 |
| 합친 뒤 선택 | 다른 레이어끼리 합쳤을 때만 선택 해제. 같은 레이어 병합은 예전처럼 결과를 다시 선택한다 | 원본이 그대로 남아 있어 "합쳐진 것"을 다시 선택해 두면 헷갈린다. 제자리 병합은 원본이 없으니 그 문제가 없다 |

## 동작

| 상황 | 결과 |
|---|---|
| 2개 미만 선택 | 지금처럼 안내하고 중단 |
| 포인트 포함 | 지금처럼 거부 |
| 폴리곤과 라인이 섞임 | 지금처럼 거부 |
| 한 레이어 안에서 선택 | 원본 피처를 빼고 합친 도형을 그 레이어에 넣는다 (**변경 없음**) |
| 두 개 이상 레이어에 걸쳐 선택 | 원본을 그대로 둔 채, 합친 도형 1개만 담은 벡터 레이어를 새로 추가한다 |

떨어져 있는 폴리곤을 합치면 `turf.union`이 MultiPolygon을 돌려준다. 지금과 같고, 따로 다루지 않는다.

합친 뒤 상태표시줄 문구:
`레이어 2개의 피처 3개를 합쳐 'A + B 병합' 레이어를 만들었습니다.`

(`'…'을` 이 아니라 `'…' 레이어를` 인 것은, `uniqueName` 이 뒤에 번호를 붙이면 조사가 `를` 로 바뀌기 때문이다)

## 속성 합치기 규칙

선택한 피처가 다음과 같을 때

| 피처 | 시군구 | 인구 | 면적 | 비고 |
|---|---|---|---|---|
| A (레이어 1) | 강남구 | 53만 | 39.5 | |
| B (레이어 2) | 서초구 | 41만 | | 관측소 |

결과는 `{ 시군구: '강남구', 인구: 94만, 면적: 39.5, 비고: '관측소' }`.

- 필드 순서는 처음 등장한 순서 (다만 `2020` 같은 정수꼴 이름은 JS 객체 성질상 앞으로 당겨진다. 원본 레이어의 속성 테이블도 같은 순서로 보이므로 어긋나 보이지는 않는다)
- 숫자 필드는 합계 (값이 없거나 유한한 숫자가 아닌 쪽은 0으로 친다)
- 숫자가 아닌 필드는 값이 있는 첫 피처의 값. `null`·빈 문자열은 건너뛴다
- 같은 레이어끼리는 스키마가 같으므로 **필드 구성이 지금과 같다**. 값이 달라지는 경우는
  첫 피처의 값이 비어 있을 때뿐이고, 그때는 다음 피처의 값을 쓴다 (지금은 빈 값이 그대로 남는다).
  의도한 개선이다

## 수치 판별 — 「지금 규칙 유지」에서 고친 것

구현 검토에서 규칙을 두 번 손봤다. 한 번은 고쳤고, 한 번은 고치려다 되돌렸다.

### 고친 것 — 빈 칸은 타입의 근거가 못 된다

```
[{인구: null}, {인구: 530000}, {인구: 410000}]
   옛 규칙 → 530000   (첫 칸이 비어 있으니 수치 필드가 아니라고 판정)
   지금    → 940000
```

공공 GeoJSON 은 빈 칸을 `null` 로 두는 일이 흔하다. 그래서 수치 여부를
'그 필드가 **처음 등장한** 피처'가 아니라 '그 필드에 **값이 처음 들어 있는** 피처'로 판단한다.

### 되돌린 것 — 숫자로 보이는 문자열은 더하지 않는다

한때 주제도의 필드 고르기와 기준을 맞추려고 `src/utils/layerSelect.js` 의 `isNumericValue`
(`"103"` 도 숫자로 보는 함수)를 쓰기로 했다. 근거는 "GeoJSON·셰이프파일 로더가 숫자를
변환하지 않는다"였는데, **변환하지 않는다는 것과 원본이 문자열이라는 것은 다른 이야기**였다.
번들 데이터의 실제 타입을 보면 이렇다.

| 데이터 | 문자열로 들어오는 필드 | 숫자로 들어오는 필드 |
|---|---|---|
| `대한민국 시군구.geojson` | `code` `'11110'`, `sido` `'11'`, `base_year` `'2025'` | — |
| `대한민국 시도.geojson` | `code` `'11'`, `base_year` `'2025'` | — |
| `세계 국가.geojson` | `ISO_A2`, `CONTINENT` … | `POP_EST` `889953`, `GDP_MD` `5496` |

**더해야 할 양(인구·GDP)은 이미 숫자고, 문자열로 오는 건 더하면 안 되는 코드·연도뿐이었다.**
`isNumericValue` 를 쓰면 얻는 것은 없고, 시군구 두 개를 합칠 때마다
`code: 22250`, `sido: 22`, `base_year: 4050` 이 된다. `parseFloat` 는 앞자리만 숫자면 먹으므로
지번 `'123-4' + '567-8' = 690`, 코드 `'01' + '02' = 3` 까지 번진다.
게다가 합치기는 **원본을 지우는** 연산이고 되돌리기에 걸리지 않아 복구가 안 된다.

그래서 합치기는 **유한한 `number` 만** 더한다 (`isSummable`). 필드 고르기가 헛다리를 짚는 건
다시 고르면 그만이지만, 합계가 코드를 더해 버리면 그렇지 않다. **고르기와 더하기의 기준이
다른 것은 의도된 것이다.** 문자열로 들어오는 수치 컬럼이 실제로 문제가 되면, 고칠 자리는
합치기가 아니라 로더다 — CSV·XLSX 로더(`TableLoader.js`)는 이미 거기서 숫자로 바꾼다.

## 새 레이어 색 — 자동 색에 맡길 수 없었던 이유

처음엔 색을 지정하지 않고 자동 색에 맡기기로 했다. 구현 검토에서 그러면 안 되는 것이 드러났다.

- `pickAutoColor` 는 팔레트를 순서대로 도는 카운터일 뿐, **이미 쓰이는 색을 보지 않는다.**
- 팔레트의 **첫 색이 흰색**(`#ffffff`)이다.
- 색을 명시해서 만든 레이어는 카운터를 올리지 않는데, 프로젝트를 저장하면 모든 레이어의
  색이 함께 저장되고 다시 열 때 그 색으로 복원된다. 즉 **프로젝트를 다시 열면 순번이 0** 이다.

그래서 "프로젝트 열기 → 두 레이어에 걸쳐 선택 → 합치기"라는 이 기능의 주된 흐름에서
결과가 **불투명한 흰 면으로 맨 위에** 얹혔다. 밝은 배경지도 위에서는 아무것도 안 보여
합치기가 실패한 것처럼 보인다.

지금은 이미 쓰이는 색을 제외하고 팔레트에서 직접 고른다. 흰색은 후보에서 뺀다.
팔레트를 다 쓴 경우에도 자동 색으로 떨어뜨리지 않고 회색을 쓴다 — 떨어뜨리면 같은 문제가 되돌아온다.

3. 다른 레이어 폴리곤 3개 (레이어 3개) → 이름이 `A 외 2개 병합`

## 하지 않는 것

- 원본 삭제 옵션 (체크박스·대화상자)
- 같은 레이어 합치기를 새 레이어 방식으로 바꾸는 것
- 포인트 합치기
- 병합 결과에 원본 레이어 이름을 기록하는 필드 — 피처가 1개로 합쳐지므로 담을 곳이 마땅치 않다
