# eGIS - 교육용 GIS 웹 애플리케이션

> **최종 갱신일: 2026-09-02.** 이 문서는 "앞으로 만들 것"을 적은 기획서가 아니라, **지금 무엇이 되어 있고 무엇을 하지 않기로 했는지**를 기록해 다음 판단을 돕는 살아 있는 PRD다. 2025-12 최초 작성 이후 대부분의 기능이 구현되어 처음으로 현재 상태에 맞춰 갱신했다.

## 프로젝트 개요

eGIS는 GIS를 처음 접하는 교사와 학생들이 두려움 없이 시작하고, 나중에 QGIS로 자연스럽게 전환할 수 있도록 돕는 교육용 GIS 웹 애플리케이션입니다.

### 포지셔닝

```
완전 초보                              전문가
   │                                      │
   ▼                                      ▼
┌──────────┐    자연스러운 전환    ┌──────────┐
│   eGIS   │ ──────────────────▶ │   QGIS   │
│ (교육용)  │                      │ (전문가용) │
└──────────┘                      └──────────┘
```

## 문제 정의와 대상 사용자

GIS 수업은 QGIS 같은 전문 데스크톱 프로그램으로 시작하기 어렵다. 설치에 관리자 권한이 필요하고 용량이 500MB를 넘는데, 학교 컴퓨터실·크롬북·태블릿은 대개 설치 권한이 없거나 사양이 낮다. 기능이 수백 개라 QGIS 문서를 처음 읽는 사람이 "지도를 불러와서 뭔가 해본다"까지 가기 전에 수업 시간이 끝난다. 그 결과 GIS 수업은 교사 시연 위주로 흐르거나 커리큘럼에서 빠지기 쉽다.

eGIS는 이 간극을 메우는 징검다리다. 대상은 GIS를 처음 접하는 중·고등학교 지리 교사와 학생이며, 다음 제약을 전제로 설계한다.

- **기기**: 크롬북·태블릿·구형 PC 등 설치 권한이 없거나 사양이 낮은 기기
- **시간**: 한 차시(45~50분) 안에 접속부터 결과물까지 끝나야 한다
- **숙련도**: GIS 용어를 처음 접하는 사용자. 좌표계·투영법을 몰라도 결과가 맞아야 한다

브라우저 URL 하나로 실행되고, 핵심 기능만 남기고, 튜토리얼과 샘플 데이터를 내장해 이 제약 안에서 "직접 해보는 수업"이 가능하게 하는 것이 존재 이유다.

### QGIS 대비 차별점

| 구분 | eGIS (교육용) | QGIS (전문가용) |
|------|---------------|-----------------|
| 설치 | 없음 (웹 브라우저) | 필요 (500MB+) |
| 접근성 | URL만 있으면 어디서든 | 설치된 PC에서만 |
| 학습 곡선 | 완만함 | 가파름 |
| 기능 수 | 핵심만 엄선 | 수백 개 |
| 튜토리얼 | 계획했으나 미구현 (아래 「교육/연수 기능」 참고) | 외부 문서/영상 |
| 저장 | 클라우드 저장으로 기기 간 이어서 작업 (실시간 공동편집·공유는 없음) | 불편함 |
| 대상 | GIS 입문자, 교사 연수 | 전문가, 연구자 |

## 범위 밖 (Non-goals)

이 프로젝트가 하지 않기로 한 것들이다. 코드와 설계 문서에 근거가 있는 것만 적는다.

- **QGIS를 대체하지 않는다.** 포지셔닝 자체가 "징검다리"다. 전문가가 QGIS 대신 상시로 쓰는 도구가 되는 것은 목표가 아니다.
- **전문가용 편집·품질 검사는 하지 않는다.** 위상(topology) 검사, 지오메트리 정합성 자동 복구 같은 전문 GIS 기능은 없다. `FeatureEditGeometry.js`·`HistoryManager.js`는 수업에서 쓰는 단위(그리기·수정·삭제·합치기)까지만 다룬다.
- **임의의 좌표계를 정의할 수 없다.** `CoordinateSystem`에 등록된 한국 실무 좌표계 16종(Korea 2000·Korean 1985 4원점 계열, UTM-K, UTM 51/52N, WGS84, Web Mercator)만 지원한다. EPSG 코드를 직접 입력해 임의 좌표계를 등록하는 기능은 없다.
- **실시간 공동편집·프로젝트 공유는 하지 않는다.** Supabase 클라우드 저장은 같은 사용자가 기기 간 이어받는 용도까지다. 여러 사용자가 같은 프로젝트를 동시에 편집하거나 다른 사람과 공유하는 기능은 코드에 없다.
- **오프라인 동작을 지원하지 않는다.** 서비스 워커·매니페스트가 없다. 접속 상태를 전제로 한다.
- **다국어를 지원하지 않는다.** 한국어 단일 UI다. i18n 레이어가 없다.
- **소셜 로그인은 구글만 지원한다.** 카카오 로그인은 만들지 않았다.
- **가져온 레이어의 좌표계를 나중에 재지정할 수 없다.** 레이어는 가져올 때 EPSG:3857로 변환해 저장하고 원본 좌표계는 메타데이터(`sourceCrs`)로만 남긴다. 저장된 레이어를 다른 좌표계로 재지정하는 기능은 설계 단계에서 범위 밖으로 정했다(`docs/superpowers/specs/2026-09-01-crs-auto-detect-design.md` 「범위 밖」) — 3857→원본→새 좌표계로 두 번 변환해야 하는데 레이어 메타·프로젝트 저장 형식이 함께 바뀌어야 해서 별도 작업으로 미뤘다.
- **DEM은 픽셀을 재투영하지 않는다.** 좌표계가 다른 DEM을 불러와도 경계상자(bbox)만 좌표 변환하고 픽셀 격자는 원본 그대로 얹는다. 정밀한 래스터 재투영은 범위 밖이다.
- **공공데이터 중계는 주소만 있는 데이터를 다루지 않는다.** 지오코딩이 필요한 자료는 등록 대상에서 제외한다(`api/_catalog.js` 등록 기준).

## 기술 스택

| 구분 | 선택 | 비고 |
|------|------|------|
| 프론트엔드 | Vite + Vanilla JavaScript | 프레임워크 없음 |
| 지도 라이브러리 | OpenLayers 9 + proj4 | GIS 기능 풍부, 좌표계 지원, QGIS와 유사 |
| 백엔드/DB | Supabase (PostgreSQL + Auth) | 로그인·프로젝트 저장 |
| 벡터 분석 | Turf.js | Buffer, Intersection 등 |
| 래스터 처리 | geotiff.js | DEM 파싱 및 분석 |
| 그래프 분석 | ngraph.graph + ngraph.path | 등시선·최단경로 분석용 |
| 파일 파싱 | shpjs (SHP), sql.js (GPKG), PapaParse (CSV), SheetJS/xlsx (XLSX) | |
| 수식 계산 | mathjs | 필드 계산기 |
| 차트 | Chart.js, D3 (d3-contour) | 도형표현도, 등고선 |
| 내보내기 | html2canvas + jsPDF, @mapbox/shp-write | 이미지/PDF, SHP 내보내기 |
| 공공데이터 중계 | Vercel Serverless Functions (`api/`) | 인증키 서버 보관, CORS 우회 |
| 외부 API | OpenRouteService(경로·등시선), Nominatim(지오코딩) | 개인정보 위탁 목록에 명시 |

튜토리얼 후보였던 intro.js·shepherd.js는 `package.json`에 없다 — 「교육/연수 기능」 참고.

## 인터페이스 설계

QGIS와 유사한 레이아웃으로 구성하여 추후 QGIS 전환 시 적응이 쉽도록 함.

```
┌─────────────────────────────────────────────────────┐
│  메뉴바 (프로젝트 | 편집 | 보기 | 레이어 | 분석)     │
├─────────────────────────────────────────────────────┤
│  툴바 (선택, 이동, 확대, 그리기, 측정, 분석 등)      │
├────────┬────────────────────────────┬───────────────┤
│ 브라우저│                            │               │
│ 패널   │       맵 캔버스             │   처리 도구   │
│        │      (OpenLayers)          │     패널      │
├────────┤                            │   - Buffer    │
│ 레이어 │                            │   - Intersect │
│ 패널   │                            │   - DEM분석   │
│        │                            │   - 등시선    │
├────────┴────────────────────────────┴───────────────┤
│  상태표시줄: 좌표 | 축척 | CRS | 방문자 수           │
└─────────────────────────────────────────────────────┘
```

모바일·태블릿에서는 하단 시트 레이어 패널, 아이콘 메뉴, 접이식 툴바, 전체 화면 속성 테이블로 바뀐다.

## 핵심 기능

### 1. 데이터 불러오기

- [x] SHP, GPKG, GeoJSON 파일 업로드 (드래그 앤 드롭)

- [x] 실습 데이터 카탈로그 (`public/data/builtin/practice_catalog.json`, `docs/practice-data-guide.md`)

### 2. 공공데이터 불러오기 (계획에 없던 항목, 크게 구현됨)

원본 요구사항 문서에는 없었지만 실제로는 앱의 핵심 데이터 소스다.

- [x] 서울열린데이터광장(351종)·경기데이터드림(718종)·인천데이터포털(4종) + 공공데이터포털(전기차 충전소) — 합계 1,070여 종(`api/_catalog.js`, `_catalog.seoul.js`, `_catalog.gg.js`, `_catalog.incheon.js`)
- [x] 앱 안에서 지역(시도)·이름·설명으로 검색해 바로 지도에 추가
- [x] 불러온 자료를 포인트 레이어·격자 집계·히트맵 중 하나로 바로 변환
- [x] 서버가 인증키를 보관하고 중계(Vercel Serverless Functions) — 브라우저에 엔드포인트·서비스키를 노출하지 않음
- [x] 대용량 응답은 페이지네이션으로 전량 수집 (예: 전기차 충전소는 시군구 단위로 나눠 병렬 수집)
- [x] 좌표계 변환은 브라우저에서 proj4로 수행 — 서버 함수는 가볍게 유지

### 3. 좌표계 자동 감지 (계획에 없던 항목, 크게 구현됨)

원본 요구사항 문서는 "CRS 변환 지원"만 적혀 있었다. 실제로는 원본 좌표계를 자동 판정하는 별도 시스템이 있다.

- [x] 판정 순서: `.prj`/GeoPackage `srs_id`/GeoJSON `crs` 멤버의 EPSG 코드 → `.prj` 투영 파라미터 매칭 → 좌표 역검증(후보 좌표계로 EPSG:4326에 되돌려 한국 영역에 떨어지는지 확인)
- [x] 확신할 수 있으면 조용히 변환, 애매하면 후보를 지도에 미리 그려 보여주는 확인 창(`CrsConfirmDialog`)에서 선택
- [x] 한국 실무 좌표계 16종 지원 (Korea 2000·Korean 1985 4원점 계열, UTM-K, UTM 51N/52N, WGS84, Web Mercator)
- [x] 5개 로더(GeoJSON·Shapefile·GeoPackage·표·DEM) 전부가 같은 판정 모듈(`CrsDetector`)을 공유

## 성공 지표

앱 상태표시줄에 방문자 카운터가 있다(`src/core/VisitorTracker.js`). 무엇을 세는지:

- **일일 방문자 수**: 같은 기기는 하루 1회만 센다(방문 일자를 로컬스토리지에 기록해 중복 방지). 그날 처음 접속한 기기 수를 뜻한다.
- **누적 방문자 수**: 일별 방문자 수를 날짜별로 구글 시트에 쌓은 합계(`scripts/viewership.gs`, Google Apps Script Web App).

지금 세는 값은 "얼마나 접속했는가"뿐이다. 어떤 기능을 얼마나 썼는지, 수업에서 끝까지 완료했는지는 세지 않는다. 이 문서는 무엇을 지표로 삼을지만 정하고, 실제 숫자를 지어내지 않는다 — 확인하려면 앱 상태표시줄이나 구글 시트를 본다.

`supabase-page-views.sql`은 예전에 검토됐던 다른 방식(Supabase 테이블 기반)이고, 지금 코드가 실제로 쓰는 것은 위 Apps Script + 구글시트 방식이다. `page_views` 테이블을 참조하는 코드는 현재 없다.

## 의사결정 기록 (ADR)

되돌리려는 사람을 막기 위한 절이다. 대부분 2026-09-01~02 좌표계 자동 감지 작업에서 나왔다.

### 좌표계 정의는 `CoordinateSystem` 한 곳에만 둔다

`src/core/CoordinateSystem.js`의 `CRS_DEFINITIONS`가 유일한 출처다. 로더는 여기서 읽기만 하고 직접 `proj4.defs`를 등록하지 않는다. 예전에는 `ShapefileLoader`가 같은 좌표계를 다른 towgs84 값으로 중복 등록했다 — `proj4.defs`는 `if (!proj4.defs(code))` 가드를 쓰므로 먼저 평가되는 쪽이 이겼고, `CoordinateSystem`의 정의가 조용히 묻혔다.

### Bessel 계열(Korean 1985) 좌표계는 towgs84 7파라미터를 쓴다

앞 세 개(평행이동)만 쓰면 회전·축척이 빠져 어긋난다. 서울 인허가 병원 638곳으로 검증한 결과:

| 방식 | 중앙 오차 |
|---|---|
| 3파라미터(평행이동만) | 17.7m |
| 7파라미터(우리 정의) | 5.6m |
| EPSG 공식 7파라미터 | 18.2m |
| 데이텀 이동 없음 | 362.7m |

국내 공공데이터 `.prj`가 선언하는 값과 같은 한 벌(`-115.8, 474.99, 674.11, 1.16, -2.31, -1.63, 6.43`)을 쓴다. EPSG 공식값(`-145.907, 505.034, 685.756, …`)은 다른 한 벌이라 섞지 않는다 — 같은 벌 안에서만 뜻이 있다.

### shpjs에 `.prj`를 넘기지 않는다

shpjs는 `.prj`가 있으면 스스로 WGS84로 재투영하는데, 그 변환은 `.prj`에 적힌 값만 쓴다. 국내 공공데이터의 `.prj`는 TOWGS84가 빠진 경우가 흔해 데이텀 이동이 생략되고 약 360m 어긋난다(제주 `LSMD_CONT_UM102_5174` 실측). `stripPrj`로 zip에서 `.prj`를 걷어내고 shpjs에는 지오메트리만 읽게 한다 — 좌표 변환은 `CoordinateSystem`의 정의로 우리가 직접 한다.

URL로 직접 불러오는 경로(`loadFromUrl`)는 `.prj`를 뗄 수 없다. shpjs가 재투영해 좌표가 이미 경위도로 보이면 `.prj`를 판정 근거에서 빼는 것으로 이중 변환만 막는다 — 이중 변환을 방치하면 서울 LSMD 파일 기준 참값에서 590km 벌어진다.

### 좌표계 정의는 우리가 정한 것과 파싱 라이브러리 것을 섞지 않는다

파싱 라이브러리가 좌표를 건드리는지 먼저 확인한다 — 위 shpjs 사고의 교훈이다. GeoJSON·GeoPackage·DEM·표 로더는 원본 좌표를 그대로 주므로 이 문제가 없다. 앞으로 파싱 라이브러리를 바꾸거나 추가할 때, 그 라이브러리가 내부적으로 좌표를 재투영하는지부터 확인해야 한다.

### 좌표만으로 갈리지 않으면 확정하지 않는다

`.prj`도 `srs_id`도 없는 순수 TM 좌표는 후보가 8~10개까지 남을 수 있다. 한국 영역 상자(경도 8°×위도 10°)가 중부·동부·서부·동해 4원점(2~4° 간격)과 GRS80·Bessel 데이텀을 가르기엔 느슨하기 때문이다. 상자를 좁히면 백령도·독도가 잘려 나가 간단히 조일 수 없다 — 좌표만으로는 원리상 갈릴 수 없는 것이 맞다. 그래서 후보를 지도에 미리 그려 사용자가 위치를 보고 고르게 한다(`CrsConfirmDialog`). 조용히 틀리는 것보다 묻는 편이 낫다는 판단이다.

### `core/`는 되도록 `ui/`를 직접 import하지 않는다

좌표계 확인처럼 core 로직이 필요로 하는 UI는 콜백으로 주입받는다. `crsResolver.js`는 `setCrsPrompt(fn)`으로 `CrsConfirmDialog`를 주입받고, `main.js`가 시작할 때 한 번 등록한다. 그래야 `crsResolver`·`CrsDetector` 같은 core 모듈이 DOM 없이 단독 테스트된다. (예외: `MapManager`는 `ui/MapScaleBar`를, `ConsentManager`는 `ui/panels/PrivacyPolicyPanel`의 상수를 직접 import한다 — 이 규칙은 좌표계 확인 흐름처럼 테스트 격리가 중요한 곳에 적용된 것이지 `core/` 전체에 대한 절대 규칙은 아니다.)

### 그 밖에 코드에 남은 판단들

- **명시적 근거의 모순 검사는 한국 자료에서만 작동한다.** `.prj`가 선언한 좌표계로 표본을 되돌렸을 때 한국 밖에 떨어지고, 다른 후보가 한국 안에 떨어질 때만 확정을 낮춘다. 해외 자료를 오작동시키지 않으려는 대가로, 해외 자료끼리의 모순은 잡지 못한다.
- **GeoPackage의 `srs_id`는 검증 후 쓴다.** 예전에는 `'EPSG:' + srs_id`를 그대로 문자열로 만들어 미등록 코드에서 변환이 실패했다. 지금은 아는 코드인지 확인하고, 모르면 좌표 역검증으로 넘긴다.
- **DEM은 확인 창을 띄우지 않는다.** 픽셀을 재투영하지 않고 bbox만 변환하는 구조라 미리보기로 그릴 것이 없다. `ambiguous`일 때 첫 후보를 쓰고 `console.warn`만 남긴다.
- **레이어 합치기에서 숫자로 보이는 문자열은 더하지 않는다.** 코드·연도(`'11110'`, `'2025'`) 같은 값이 합계에 섞이면 되돌릴 수 없어, 실제 `number` 타입인 값만 더한다(`isSummable`). 한때 문자열도 숫자로 변환해 더하기로 했다가 되돌렸다.
